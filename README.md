# SingMic —— 手机当麦克风,电脑当调音台

把手机变成一支无线麦克风:手机浏览器采集声音,通过局域网/端口转发送到电脑,
电脑上做降噪、EQ、齿音抑制、压缩、混响,再走耳返,同时把干声和成品录下来。

配套一个多轨工作室(类似 FL Studio 的网页界面):可以摆人声块、加伴奏、
用钢琴卷帘写旋律、修音高、加效果器和母带,最后导出 WAV / MP3。

> 录音只保存在你自己的电脑上,不上传、不联网。服务默认只监听本机。

## 特性

| 模块 | 做什么 |
|---|---|
| **手机端** `/phone` | 采集麦克风、显示电平、自报采样参数;支持把页面放后台继续收音(需系统允许) |
| **控制台** `/` | 设备选择、增益/降噪/门/EQ/齿音/压缩/混响、电平表、录音与导出 |
| **实时耳返** | 低延迟输出到指定设备;耳返走 AI 之前的一路,省掉模型延迟 |
| **伴奏** | 抓取电脑正在播放的声音(WASAPI 环回),与麦克风混音;也可用 `music/` 里的文件 |
| **AI 降噪** | 可选,DeepFilterNet3(48k);包或模型不在时自动降级,主路照常出声 |
| **音符块编辑器** | 把一条人声切成块,逐块改音高/长度/删除,原录音只读 |
| **工作室** `/studio` | 多轨、BPM 网格、吸附/量化、变调、采样池、钢琴卷帘、和声、和弦检测、混音台、**每轨插入效果链**、**VST3 插件(离线 + 冻结轨)**、每轨混响/延迟、LUFS 母带、导出 WAV/MP3、**分轨导出** |

## 安装

需要 **Python 3.11+**(用到 `tomllib`)。

```bash
python -m pip install -r requirements.txt
```

可选(AI 降噪):

```bash
python -m pip install deepfilter_stream
# 模型已在 _ai_try/model/,不用另外下载
```

可选(VST3 插件):

```bash
python -m pip install -r requirements-vst.txt   # pedalboard, GPL-3.0
# 不装也能跑,只是「VST」页里显示黄字「宿主不可用」
```

## 跑起来

Windows 双击 `start.bat`,或者手动:

```bash
adb reverse tcp:8765 tcp:8765     # 把手机的 8765 转发到电脑(USB 或同一局域网也可)
python server.py
```

然后在电脑上打开 <http://127.0.0.1:8765/>,手机上打开 <http://127.0.0.1:8765/phone>。

- 手机和电脑不在同一台设备上时,用 `adb reverse`(USB)最稳;也可以直接访问电脑的局域网 IP。
- `/phone` 只是采集端,真正的处理全在电脑上。
- 需要改端口就改 `server.py` 底部的 `uvicorn.run(...)`。

## 配置

`config.toml` 是启动时的默认值。网页上的滑杆改的是运行中的引擎,**不会自动写回文件**;
调好以后按界面上的「保存」才会落盘。

- `[audio] output`:耳返设备名,「包含」即可,留空 = 系统默认输出。
- `[backing] source`:伴奏来源设备(环回)。**不能和 `[audio] output` 同一台**,否则啸叫。
- `[voice]`:增益、降噪、门、EQ、齿音、压缩、混响、AI 开关。

## 录音与工程

- 每次录音写三个文件:`<时间>_voice.wav`(干声)、`<时间>_mix.wav`(成品)、
  `<时间>.json`(元数据,含采集参数)。
- 原录音**只读**:所有修音/剪辑都写进工程或 `.edits.json`,不会回写源文件。
- 工作室的变调片段按内容寻址缓存(`projects/cache/clip_<key>.wav`),
  同一个片段重复使用不会重算;界面上「缓存」按钮可以看到占用并清理没被引用的。
- 导出默认做 BS.1770 响度归一化(-14 / -9 LUFS)+ 5ms 前瞻限幅。

## 每轨效果链

混音台每条轨下面有一排插件芯片,底部「效果器」页可以增删、上下移、旁通、调参。
顺序就是处理顺序,**最多 24 个**;链只作用于这一轨,排在混响/延迟之前。

| 组 | 插件 |
|---|---|
| 滤波 | 滤波(低通/高通/带通)、3 段 EQ(低架/峰/高架) |
| 动态 | 压缩(阈值/比率/启动/释放/软拐点/补偿增益)、限幅(天花板/释放) |
| 失真 | 失真(驱动/音色/干湿) |
| 调制 | 合唱、镶边(带反馈)、颤音 |
| 破坏 | 比特压缩(位深/采样保持/干湿) |

★ **播放和导出是同一套算法**:浏览器里跑 `fxworklet.js`,导出时跑 `studio_fx.py`,
两边逐行对照(自测里有一条 worklet ↔ numpy 逐点比对,`max diff = 0`)。
所以「听到的 = 导出的」这条在效果链上也成立。

★ 参数范围与默认值只有一份(`studio_fx.FX_TYPES`),界面从 `GET /api/studio/fx_types` 读,前端不另抄。

## VST3 插件(离线渲染)

底部多了一个 **「VST」页**,可以把真正的第三方 VST3 挂到轨上。

### 怎么用(3 步)

1. 把 `.vst3`(**解压后的整个文件夹**,不是压缩包)放进 `vst/`,或者装到系统的
   `C:\Program Files\Common Files\VST3`。点「刷新」就能看到。
2. 选中一条轨,在 VST 页把插件加进这条轨的链里(每轨最多 8 个,可旁通、可上下移)。
3. **勾上「冻结这一轨」**。之后正常播放这条轨时听到的就是带 VST 的声音。

### 为什么必须「冻结」

**浏览器加载不了 VST3** —— Chromium、Electron、Tauri 都一样。插件只能由本地 Python 进程
(经 `pedalboard`)离线跑,所以:

- 不冻结:实时播放里**没有** VST,只有导出才有;
- 冻结:把「轨道增益 → 内置效果链 → VST」算成一条 WAV(`projects/cache/track_<sig>.wav`),
  正常播放直接播这条结果 ⇒ 多轨同步、推子、声像照常,只是这一轨的音频换成了烘焙好的。
- 改了参数/片段/推子:轨头立刻出现黄标「正在重算…」,防抖 400ms 后自动重算并无缝换 buffer;
  重算期间仍播上一次的结果,不会突然变干声。
- **导出永远按工程现场重算**,不读冻结缓存。

### 边拉边听:短段试听

整曲重算太慢,所以 VST 页有「试听这一段(循环 4s)」:只算当前循环区(没有就取播放头后 4 秒),
拖参数时每 150ms 刷新一次,**能听出变化方向**,但不是原生 DAW 那种逐采样连续的旋钮。
旁边「听干声 A/B」用同一段做 `bypass`,来回对比。页面会显示最近一次的往返耗时。

### 诚实的边界

- **不是实时的**:插件在 Python 子进程里离线算,正常播放靠冻结。
- **有的插件每次渲染会略有不同**(内部随机 / LFO free-run / 自带 dither,比如 Airwindows
  Consolidated 就带抖动)。冻结时会连跑两遍比对,不一样就把 `nondet` 记下来,
  界面上写「这个插件每次渲染可能略有不同,冻结只是预览」—— 不装作每次都一样。
- **只存参数,不存插件自己的 preset/state**(pedalboard 没有这个 API)。
- **单声道**:轨道是单声道。只吃立体声的插件(例如 Dragonfly 四个混响,声明 2 进 2 出)
  会把同一条音频复制成 L/R 再喂进去,输出取平均合回单声道 —— 能正常用,但立体声宽度没有了。
  真需要立体声宽度,请用「分轨」导出后去别的宿主里做。
- **空轨不冻结**:这一轨一个片段都没有时,状态显示「这一轨还没有音频,不用冻结」,
  不会产出 0 采样的 WAV(那种文件浏览器解不了,会误报成「插件坏了」)。
- **只认 x86_64-win 的 `.vst3`**;`.vst2` / 裸 `.dll` 不支持。
- 插件路径是**本机的**,工程换台机器要重新指插件。
- 插件崩溃 = 这次渲染失败并报错停下(带轨名),**不会静默出干声**。
- 允许目录:`vst/` 与系统的 `Common Files\VST3`;其它路径一律拒绝(可用环境变量
  `SINGMIC_VST_DIRS` 追加,路径分隔符用 `;`)。
- **许可证**:`pedalboard` 是 **GPL-3.0**,而且只在独立子进程里被调用、不装也能跑主程序;
  插件本身的许可证由使用者自己负责。

## 分轨导出(给 FL / 别的 DAW)

顶部「分轨」按钮把每条轨单独导成 48k / 24-bit 单声道 WAV,打成一个 zip:

- 默认 = **插件链之前**(只含轨道增益,不含声像);
- 按住 Alt 点 = **插件链之后**;
- zip 里还有 `manifest.json`(轨名/长度/采样率)、`project.json`(原工程)和 `README.txt`。

拿到分轨后,任何宿主都能接着做。代码里还预留了 `studio_external.ExternalRenderer` 协议和
`export` 的 `pipeline: "external"` 分支(当前没有实现,选择它会明确返回「还没接外部渲染器」)。

## 已知限制

- **延迟是物理账**:手机采集 + 传输 + 耳返,本机实测在几十毫秒量级;蓝牙设备更差。
- **蓝牙耳机通话会掉到 8k 左右**:手机连耳机时浏览器走 SCO,高频没了、还自带降噪。
  要手机麦克风的音质,就把耳机从手机上断开。
- **块长跟着设备走**:蓝牙走共享模式,设备周期 10ms,硬改成 5ms 会得到「断断续续」。
- **「回音」只出现在耳返那一路**,录下来的文件里没有。
- **变调是 PSOLA 切片重排**,±7 半音内自然,±12 会有颗粒感;一个采样只有一种音色。
- **和弦检测会被鼓和人声干扰**,只用来建议和声。
- 工作室不做:鼓机、MIDI 输入、变速曲的 tempo map。
- **VST 只能离线跑**:必须冻结这一轨才能在正常播放里听到;短段试听是每 150ms 刷新一段 4 秒循环,
  不是连续的实时旋钮。真正的「边转边连续出声」还没做。
- **限幅不做前瞻**:瞬态会漏过去一点;母带那道的 5ms 前瞻限幅仍然兜底。
- **导出参数取稳态值**:播放时拉滑杆有 20ms 平滑,导出直接按最终值算 —— 静态对比逐点一致,
  「边拉边导」不保证。
- **采样率不同会有细微差别**:浏览器可能是 44.1k,导出固定 48k;Hz 类参数一致,
  但按块更新的系数和比特压缩的保持长度会差一点。
- **效果器需要安全上下文**:`127.0.0.1` / `localhost` 可用;用局域网 IP 从别的设备打开时
  `AudioWorklet` 可能不可用,此时播放旁通、界面顶部有黄字提示,**导出不受影响**。
- **CPU**:每轨一个 worklet,建议每轨不超过 8 个插件;不做自动旁通。

## 2026-10-20:逐音精修 + 原唱条(两种修音,一张图上配合)

> 「块编辑」页头部多了 **块 / 音高** 两个视图。默认还是「块」(摆位置);
> 切到「音高」就是 Melodyne 那种:**每个音是一块,上下拖 = 改音高**。

### 手动精修(逐音)

- 竖向拖:默认**吸附到半音**;按住 **Alt** = 按音分(0.1¢)。
- 横向拖 = 只挪位置(一次渲染都不发);拖两边 = 改长度(曲线跟着裁)。
- 多选后拖一个:选中的音**一起走同样的 delta**。
- **改曲线**笔:在选中的音里按住拖,画这一段每个时间点的修正量(源时间,**20ms 一点**);
  **拉平** = 曲线归 0(就唱在这个音上);**清曲线** = 删掉曲线,回到原始音高。
- 双击切开、Delete 原地留空、Ctrl+Z 全退,和「块」视图一样。

### 原唱修音(和手动精修共用同一份数据)

- 头部 **原唱** → 选原唱轨 → **分析**;图上画两条线:
  **橙色 = 你现在的音高**,**青色 = 目标**(你的原始音高 + 按 mode/强度算出的修正量)。
- **按原唱修选中的音**:只改选中的那些块;没选就提示,不会偷偷整轨应用。
- 分析之后**挪过位置 / 改过长度**的音会拒绝应用(提示「挪过位置,重新分析」),
  不会拿错位的方案硬套。
- 状态栏写明「修了 N 个 · M 个没对上 · 对上 74%」;对不上就直说,不硬修。

### 硬限制(别指望它做不到的事)

- 曲线是**修正量**,硬上限 **±200 音分**;要整体搬超过两个半音,用半音拖动(常数),别用曲线。
- 音高靠**本机 YIN 测**,不是神经网络;清唱/伴奏混在一起会不准,覆盖度低时会明说。
- 笔的精度是 **20ms 一点**(不是逐采样的 Melodyne);曲线最多存 800 点。
- **气声块(kind=sound)不参与修音**,只能改时间/长度。
- 手动改音高会清掉这一块的渲染缓存,下一次播放前会短暂「渲染中」—— 这是正确行为。
- 改强度 / 模式 / 原唱轨之后要**重新分析**,目标线才会跟着变。

### 顺手修掉的一处老 bug

- `tuning._psola_core` 的最后一个基音标记用 `round()` 可能正好顶到采样数 `n`,
  `f0s[marks]` 越界,个别「长度 + 音高」组合下曲线渲染直接 500。已夹到 `n-1`,
  并在 `selftest_studio.py` 里加了边界回归。

## 按字 / 音节切分与语音识别(2026-10-20)

「切好的块」标题旁多了 **切法** 下拉:

- **按字 / 音节(默认)**:找元音核,一个核 = 一个音节。中文大致一字一块;
  英文一个词可能有多个音节,就会切成多块。长音带颤音不会被切成好几块。
- **按音(逐音)**:旧行为,按音高跳变切,一个持续音一块。

旁边的 **识别** 勾选会用语音识别给块标上字/词(只标文字,不改切法):

- 模型是 sherpa-onnx 的 Paraformer 中文 + Whisper tiny,约 190MB,
  放在 `%USERPROFILE%\.singmic\models\asr\`(dev/live 共用,只下一次);
  没下载时按钮会变成「下载识别模型」,下载支持断点续传。
- 每个音频文件的识别结果缓存在旁边 `<名字>.asr.json`,换模型版本会自动失效。

**必须知道的限制**:

- 识别模型是**语音**模型,唱出来识别率不确定;**带伴奏基本不可用**。
- Paraformer 这个导出**不返回逐字时间戳**;文字只能按「字序 + 块时长」估算对齐,
  块上会显示 `~字` 并注明「仅供参考」。文字不参与切分,边界始终以声学为准。
- 识别不可用(模型缺失/失败)只降级成没有文字,切分照常。
- `/api/blocks` 新增 `mode=note|syllable`、`lang=auto|zh|en`、`asr=true`;
  **不带 `mode` 仍走旧的「按音」**,旧脚本/旧工程不受影响。

## AI 补音(延长 / 缩短)

只处理 `kind=note` 的块。入口:检查器 **补音…**,或整页块编辑 **补音…**。

- **本地**(永远可用):缩短用 PSOLA(最多缩到 30%),延长用「最稳的一段」按基音周期
  颗粒拼接 + 40ms 等功率交叉淡化;长度精确到采样,首尾 5ms 淡入淡出,不削顶。
- **云端精修**(可选):在**你自己开的**云 GPU 上按 `cloud/README.md` 训练 RVC 模型、
  起 `cloud/serve.py`;Studio 顶部 **🎙 我的声音** 填地址与 token。
  云端失败 / 关机 / 断网会自动回落本地,并在结果里写明原因,不静默。
- 生成文件落在 `projects/media/ext_<hash>.wav`;缓存 key 含源文件指纹、区间、
  目标长度、引擎和模型版本,换模型不会命中旧文件。
- **隐私**:补音只把**选中的那一段**(≤15 秒)发到**你自己配置的**服务器;
  不发工程、不发整首歌、不发文件名/路径。
- **数据不丢**:素材/模型只放数据盘(勾「不随实例释放」)+ 快照 + OSS/COS +
  本机 `D:\singmic\voice_model\model.zip`,四件套缺一不可;关实例≠删数据,
  只有「释放」才可能删盘。
- **云端已实跑(2026-10-20,阿里云 T4)**:200 轮 / 700 秒素材 / 1h11m;
  模型 `rvc-1904dfdccbb59729`(57.6 MB + 109 MB 索引)。
  `/extend` 冷启动首段 29.0 秒,热启动「3 秒→6 秒」**0.69 秒**,显存约 1.6 GB。
  服务只绑 `127.0.0.1`,本机用 SSH 隧道接(**不让公网碰 8000**);隧道断了自动回落本地。
  部署命令与坑见 `cloud/README.md` 第 12 节。

## 自然语言调参(DeepSeek)

顶部 **💬 调音助手**:范围可选 **整曲 / 选中轨 / 选中块**,用一句听感描述
(「人声太干,加一点混响」「低频太多,收一收」「整体降 2dB」),AI 返回动作清单,
勾选后应用,一次 `Ctrl+Z` 全部撤销。

- key 在面板里填一次,存在 `%USERPROFILE%\.singmic\secrets.json`,**只写不读**,
  界面只回显掩码;也可用环境变量 `DEEPSEEK_API_KEY` 临时覆盖。
- **只发参数 + 你这句话**:不发音频、不发文件名/路径/工程名;轨道名默认匿名

## 识别实测记录与镜像安装(2026-10-20)

- **两个模型都没有逐 token 时间戳**:Paraformer 导出恒返回空;Whisper tiny 的解码器
  没有 cross-attention,`enable_token_timestamps=true` 只打警告。时间和文字**全靠估算对齐**
  (`approx` / 块上的 `~`),边界始终以声学切分为准。
- 摊时间前先按能量裁掉这段两头的静音(`_active_span`),再把字/词摊进有声段;
  否则英文末尾的词会落到静音块上。改了这段算法要同时加 `_TOK_ALGO_V`,旧 `.asr.json` 才会失效。
- 干净 TTS 语料实测:中文 9 字全对(`春天来了花儿都开了`);英文 tiny 会把
  `enchants` 拆成 `Ch ants`——**英文词级准确率明显低于中文**,这属于模型能力边界,不是对齐 bug。
- **GitHub 下载被限流/重置时**,可用 HF 镜像直接装文件(不需要整个 tar.bz2):
  `https://hf-mirror.com/csukuangfj/sherpa-onnx-whisper-tiny/resolve/main/<文件名>`,
  存到 `%USERPROFILE%\.singmic\models\asr\sherpa-onnx-whisper-tiny\`:
  `tiny-encoder.int8.onnx`、`tiny-decoder.int8.onnx`、`tiny-tokens.txt`
  (共约 104MB)。文件齐了 `/api/studio/asr/status` 就报 `ready`,不用点下载。
