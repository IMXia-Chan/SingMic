# SingMic —— 免费的本地多轨音乐工作站

在电脑上完成录音、编曲、混音、母带与导出:多轨时间线、BPM 网格、钢琴卷帘、
采样池、和弦检测、混音台、每轨效果链、VST3 插件、修音高,最后导出 WAV / MP3。

手机可作为无线麦克风:手机浏览器采集声音,通过局域网/端口转发送到电脑,
电脑上做降噪、EQ、齿音抑制、压缩、混响,再走耳返,同时把干声和成品录下来。

> 录音只保存在你自己的电脑上,不上传、不联网。服务默认只监听本机。

## 特性

| 模块 | 做什么 |
|---|---|
| **手机端** `/phone` | 采集麦克风、显示电平、自报采样参数;支持把页面放后台继续收音(需系统允许) |
| **控制台** `/` | 设备选择、增益/降噪/门/EQ/齿音/压缩/混响、电平表、录音与导出 |
| **实时耳返** | 低延迟输出到指定设备;耳返走 AI 之前的一路,省掉模型延迟 |
| **伴奏** | 抓取电脑正在播放的声音(WASAPI 环回),与麦克风混音;也可用 `music/` 里的文件 |
| **AI 降噪** | 可选,DeepFilterNet3(48k);包或模型不在时自动降级,主路照常出声 |
| **音符块编辑器** | 把一条人声切成块,逐块改音高/长度/删除,原录音只读 |
| **工作室** `/studio` | 多轨、BPM 网格、吸附/量化、变调、采样池、钢琴卷帘、和声、和弦检测、混音台、**每轨插入效果链**、**VST3 插件(离线 + 冻结轨)**、每轨混响/延迟、LUFS 母带、导出 WAV/MP3、**分轨导出** |

## 安装

需要 **Python 3.11+**(用到 `tomllib`)。

```bash
python -m pip install -r requirements.txt
```

可选(AI 降噪):

```bash
python -m pip install deepfilter_stream
# 模型已在 _ai_try/model/,不用另外下载
```

可选(VST3 插件):

```bash
python -m pip install -r requirements-vst.txt   # pedalboard, GPL-3.0
# 不装也能跑,只是「VST」页里显示黄字「宿主不可用」
```

## 跑起来

Windows 双击 `start.bat`,或者手动:

```bash
adb reverse tcp:8765 tcp:8765     # 把手机的 8765 转发到电脑(USB 或同一局域网也可)
python server.py
```

然后在电脑上打开 <http://127.0.0.1:8765/>,手机上打开 <http://127.0.0.1:8765/phone>。

- 手机和电脑不在同一台设备上时,用 `adb reverse`(USB)最稳;也可以直接访问电脑的局域网 IP。
- `/phone` 只是采集端,真正的处理全在电脑上。
- 需要改端口就改 `server.py` 底部的 `uvicorn.run(...)`。

## 配置

`config.toml` 是启动时的默认值。网页上的滑杆改的是运行中的引擎,**不会自动写回文件**;
调好以后按界面上的「保存」才会落盘。

- `[audio] output`:耳返设备名,「包含」即可,留空 = 系统默认输出。
- `[backing] source`:伴奏来源设备(环回)。**不能和 `[audio] output` 同一台**,否则啸叫。
- `[voice]`:增益、降噪、门、EQ、齿音、压缩、混响、AI 开关。

## 录音与工程

- 每次录音写三个文件:`<时间>_voice.wav`(干声)、`<时间>_mix.wav`(成品)、
  `<时间>.json`(元数据,含采集参数)。
- 原录音**只读**:所有修音/剪辑都写进工程或 `.edits.json`,不会回写源文件。
- 工作室的变调片段按内容寻址缓存(`projects/cache/clip_<key>.wav`),
  同一个片段重复使用不会重算;界面上「缓存」按钮可以看到占用并清理没被引用的。
- 导出默认做 BS.1770 响度归一化(-14 / -9 LUFS)+ 5ms 前瞻限幅。

## 每轨效果链

混音台每条轨下面有一排插件芯片,底部「效果器」页可以增删、上下移、旁通、调参。
顺序就是处理顺序,**最多 24 个**;链只作用于这一轨,排在混响/延迟之前。

| 组 | 插件 |
|---|---|
| 滤波 | 滤波(低通/高通/带通)、3 段 EQ(低架/峰/高架) |
| 动态 | 压缩(阈值/比率/启动/释放/软拐点/补偿增益)、限幅(天花板/释放) |
| 失真 | 失真(驱动/音色/干湿) |
| 调制 | 合唱、镶边(带反馈)、颤音 |
| 破坏 | 比特压缩(位深/采样保持/干湿) |

★ **播放和导出是同一套算法**:浏览器里跑 `fxworklet.js`,导出时跑 `studio_fx.py`,
两边逐行对照(自测里有一条 worklet ↔ numpy 逐点比对,`max diff = 0`)。
所以「听到的 = 导出的」这条在效果链上也成立。

★ 参数范围与默认值只有一份(`studio_fx.FX_TYPES`),界面从 `GET /api/studio/fx_types` 读,前端不另抄。

## VST3 插件(离线渲染)

底部多了一个 **「VST」页**,可以把真正的第三方 VST3 挂到轨上。

### 怎么用(3 步)

1. 把 `.vst3`(**解压后的整个文件夹**,不是压缩包)放进 `vst/`,或者装到系统的
   `C:\Program Files\Common Files\VST3`。点「刷新」就能看到。
2. 选中一条轨,在 VST 页把插件加进这条轨的链里(每轨最多 8 个,可旁通、可上下移)。
3. **勾上「冻结这一轨」**。之后正常播放这条轨时听到的就是带 VST 的声音。

### 为什么必须「冻结」

**浏览器加载不了 VST3** —— Chromium、Electron、Tauri 都一样。插件只能由本地 Python 进程
(经 `pedalboard`)离线跑,所以:

- 不冻结:实时播放里**没有** VST,只有导出才有;
- 冻结:把「轨道增益 → 内置效果链 → VST」算成一条 WAV(`projects/cache/track_<sig>.wav`),
  正常播放直接播这条结果 ⇒ 多轨同步、推子、声像照常,只是这一轨的音频换成了烘焙好的。
- 改了参数/片段/推子:轨头立刻出现黄标「正在重算…」,防抖 400ms 后自动重算并无缝换 buffer;
  重算期间仍播上一次的结果,不会突然变干声。
- **导出永远按工程现场重算**,不读冻结缓存。

### 边拉边听:短段试听

整曲重算太慢,所以 VST 页有「试听这一段(循环 4s)」:只算当前循环区(没有就取播放头后 4 秒),
拖参数时每 150ms 刷新一次,**能听出变化方向**,但不是原生 DAW 那种逐采样连续的旋钮。
旁边「听干声 A/B」用同一段做 `bypass`,来回对比。页面会显示最近一次的往返耗时。

### 诚实的边界

- **不是实时的**:插件在 Python 子进程里离线算,正常播放靠冻结。
- **有的插件每次渲染会略有不同**(内部随机 / LFO free-run / 自带 dither,比如 Airwindows
  Consolidated 就带抖动)。冻结时会连跑两遍比对,不一样就把 `nondet` 记下来,
  界面上写「这个插件每次渲染可能略有不同,冻结只是预览」—— 不装作每次都一样。
- **只存参数,不存插件自己的 preset/state**(pedalboard 没有这个 API)。
- **单声道**:轨道是单声道。只吃立体声的插件(例如 Dragonfly 四个混响,声明 2 进 2 出)
  会把同一条音频复制成 L/R 再喂进去,输出取平均合回单声道 —— 能正常用,但立体声宽度没有了。
  真需要立体声宽度,请用「分轨」导出后去别的宿主里做。
- **空轨不冻结**:这一轨一个片段都没有时,状态显示「这一轨还没有音频,不用冻结」,
  不会产出 0 采样的 WAV(那种文件浏览器解不了,会误报成「插件坏了」)。
- **只认 x86_64-win 的 `.vst3`**;`.vst2` / 裸 `.dll` 不支持。
- 插件路径是**本机的**,工程换台机器要重新指插件。
- 插件崩溃 = 这次渲染失败并报错停下(带轨名),**不会静默出干声**。
- 允许目录:`vst/` 与系统的 `Common Files\VST3`;其它路径一律拒绝(可用环境变量
  `SINGMIC_VST_DIRS` 追加,路径分隔符用 `;`)。
- **许可证**:`pedalboard` 是 **GPL-3.0**,而且只在独立子进程里被调用、不装也能跑主程序;
  插件本身的许可证由使用者自己负责。

## 分轨导出(给 FL / 别的 DAW)

顶部「分轨」按钮把每条轨单独导成 48k / 24-bit 单声道 WAV,打成一个 zip:

- 默认 = **插件链之前**(只含轨道增益,不含声像);
- 按住 Alt 点 = **插件链之后**;
- zip 里还有 `manifest.json`(轨名/长度/采样率)、`project.json`(原工程)和 `README.txt`。

拿到分轨后,任何宿主都能接着做。代码里还预留了 `studio_external.ExternalRenderer` 协议和
`export` 的 `pipeline: "external"` 分支(当前没有实现,选择它会明确返回「还没接外部渲染器」)。

## 已知限制

- **延迟是物理账**:手机采集 + 传输 + 耳返,本机实测在几十毫秒量级;蓝牙设备更差。
- **蓝牙耳机通话会掉到 8k 左右**:手机连耳机时浏览器走 SCO,高频没了、还自带降噪。
  要手机麦克风的音质,就把耳机从手机上断开。
- **块长跟着设备走**:蓝牙走共享模式,设备周期 10ms,硬改成 5ms 会得到「断断续续」。
- **「回音」只出现在耳返那一路**,录下来的文件里没有。
- **变调是 PSOLA 切片重排**,±7 半音内自然,±12 会有颗粒感;一个采样只有一种音色。
- **和弦检测会被鼓和人声干扰**,只用来建议和声。
- 工作室不做:鼓机、MIDI 输入、变速曲的 tempo map。
- **VST 只能离线跑**:必须冻结这一轨才能在正常播放里听到;短段试听是每 150ms 刷新一段 4 秒循环,
  不是连续的实时旋钮。真正的「边转边连续出声」还没做。
- **限幅不做前瞻**:瞬态会漏过去一点;母带那道的 5ms 前瞻限幅仍然兜底。
- **导出参数取稳态值**:播放时拉滑杆有 20ms 平滑,导出直接按最终值算 —— 静态对比逐点一致,
  「边拉边导」不保证。
- **采样率不同会有细微差别**:浏览器可能是 44.1k,导出固定 48k;Hz 类参数一致,
  但按块更新的系数和比特压缩的保持长度会差一点。
- **效果器需要安全上下文**:`127.0.0.1` / `localhost` 可用;用局域网 IP 从别的设备打开时
  `AudioWorklet` 可能不可用,此时播放旁通、界面顶部有黄字提示,**导出不受影响**。
- **CPU**:每轨一个 worklet,建议每轨不超过 8 个插件;不做自动旁通。

## 2026-10-20:逐音精修 + 原唱条(两种修音,一张图上配合)

> 「块编辑」页头部多了 **块 / 音高** 两个视图。默认还是「块」(摆位置);
> 切到「音高」就是 Melodyne 那种:**每个音是一块,上下拖 = 改音高**。

### 手动精修(逐音)

- 竖向拖:默认**吸附到半音**;按住 **Alt** = 按音分(0.1¢)。
- 横向拖 = 只挪位置(一次渲染都不发);拖两边 = 改长度(曲线跟着裁)。
- 多选后拖一个:选中的音**一起走同样的 delta**。
- **改曲线**笔:在选中的音里按住拖,画这一段每个时间点的修正量(源时间,**20ms 一点**);
  **拉平** = 曲线归 0(就唱在这个音上);**清曲线** = 删掉曲线,回到原始音高。
- 双击切开、Delete 原地留空、Ctrl+Z 全退,和「块」视图一样。

### 原唱修音(和手动精修共用同一份数据)

- 头部 **原唱** → 选原唱轨 → **分析**;图上画两条线:
  **橙色 = 你现在的音高**,**青色 = 目标**(你的原始音高 + 按 mode/强度算出的修正量)。
- **按原唱修选中的音**:只改选中的那些块;没选就提示,不会偷偷整轨应用。
- 分析之后**挪过位置 / 改过长度**的音会拒绝应用(提示「挪过位置,重新分析」),
  不会拿错位的方案硬套。
- 状态栏写明「修了 N 个 · M 个没对上 · 对上 74%」;对不上就直说,不硬修。

### 硬限制(别指望它做不到的事)

- 曲线是**修正量**,硬上限 **±200 音分**;要整体搬超过两个半音,用半音拖动(常数),别用曲线。
- 音高靠**本机 YIN 测**,不是神经网络;清唱/伴奏混在一起会不准,覆盖度低时会明说。
- 笔的精度是 **20ms 一点**(不是逐采样的 Melodyne);曲线最多存 800 点。
- **气声块(kind=sound)不参与修音**,只能改时间/长度。
- 手动改音高会清掉这一块的渲染缓存,下一次播放前会短暂「渲染中」—— 这是正确行为。
- 改强度 / 模式 / 原唱轨之后要**重新分析**,目标线才会跟着变。

### 顺手修掉的一处老 bug

- `tuning._psola_core` 的最后一个基音标记用 `round()` 可能正好顶到采样数 `n`,
  `f0s[marks]` 越界,个别「长度 + 音高」组合下曲线渲染直接 500。已夹到 `n-1`,
  并在 `selftest_studio.py` 里加了边界回归。

## 按字 / 音节切分与语音识别(2026-10-20)

「切好的块」标题旁多了 **切法** 下拉:

- **按字 / 音节(默认)**:找元音核,一个核 = 一个音节。中文大致一字一块;
  英文一个词可能有多个音节,就会切成多块。长音带颤音不会被切成好几块。
- **按音(逐音)**:旧行为,按音高跳变切,一个持续音一块。

旁边的 **识别** 勾选会用语音识别给块标上字/词(只标文字,不改切法):

- 模型是 sherpa-onnx 的 Paraformer 中文 + Whisper tiny,约 190MB,
  放在 `%USERPROFILE%\.singmic\models\asr\`(dev/live 共用,只下一次);
  没下载时按钮会变成「下载识别模型」,下载支持断点续传。
- 每个音频文件的识别结果缓存在旁边 `<名字>.asr.json`,换模型版本会自动失效。

**必须知道的限制**:

## 切块之后的「接缝」:为什么以前一切就抽一下

**症状**:在块中间按 `S` 切一刀,播放和导出都会在切点「抽一下」/「咔」一下。

**真因**(2026-10-21 量出来的):

以前切分是**整块深拷贝**把两块分开 —— 左半继承了原来的 20ms 淡出、右半继承了 8ms 淡入。
可是这两半在源波形上是**同一串连续样本**,时间上也首尾相接,根本不该有淡变。
两段淡变叠在接缝处,就凭空塌出一个坑:

| | 接缝处凹陷 | 宽度 |
|---|---|---|
| 老做法 | **-16.5 dB** | **27.9 ms** |
| 新做法 | **无**(与「压根没切过」逐样本完全一致) | — |

**修法**:在动过结构(切分 / 删除 / 复制 / 粘贴 / 量化 / 对齐标记 / 拖拽裁剪)之后,
重新判一遍每块的两端是不是**真接缝** —— 时间上首尾相接 **且** 源上的 `srcOut === srcIn`。

- 真接缝 → 淡变清零(那里为零才是对的)
- 断开的边(挪过、裁过、粘贴出来的)→ 至少留 **2.5ms** 淡变,把台阶磨圆,否则是一声「咔」
- 例外:**变过调 / 画过音高曲线**的块是重新渲染的,相位对不上,哪怕源上连续也得留淡变

`D:\singmic\web\studio\ui.js` 里是 `seamFades()` / `seamFadesAll()`;判据与两条冒烟断言
在 `tools/smoke_studio.py`(切分后接缝两边必须是 0;删掉一半后必须长回 2.5ms)。
播放(WebAudio)和导出(`studio_mix.py` 的 numpy)用的是同一套线性淡变公式,所以两边一致。

★ **不要**为了「保险」给所有块都加淡变 —— 那正是这次的问题本身。

## 导出的立体声:为什么以前「过一遍调音台就窄了」

**症状**:一首本来有立体声宽度的歌,导入 Studio、什么都不动、直接导出,
两声道变成**逐样本一模一样**,而且每一侧都比原曲**低 3 dB**。A/B 一听就是「闷了一层、窄了」。

**真因**(2026-10-21 量出来的):

整条混音路读的是**单声道**:`load_mono()` 把所有源压成一维,再用「等功率声像」
(居中时左右各乘 0.707)分开。两件事同时发生:

- 左右**一模一样** ⇒ 立体声宽度没了;
- 每侧 0.707 ⇒ 比原曲**低约 3 dB**。

而浏览器播放走的是 Web Audio 的 `StereoPannerNode` —— 它**读的是真立体声缓冲**,
居中原样通过、不减电平。所以「听到的」和「导出的」从根上就不是同一个东西。

**修法**(`studio_mix.py`):

| 位置 | 以前 | 现在 |
|---|---|---|
| 读源 | `load_mono()` | `load_stereo()` → (n, 2);单声道文件复制成左右两份 |
| 片段 / 音符 | 一维 | `(n, 2)`;音符(采样器音色池)是单声道 ⇒ 左右各一份 |
| 插入链 / VST / 混响延迟 | 直接吃一维 | `_per_ch()` 逐声道跑(非线性效果左右各算各的) |
| 声像 | 一维等功率 | **照抄 `StereoPannerNode`**:真立体声源用它那套平衡律,单声道源仍用等功率律 |
| 分轨 stems | 单声道 24-bit | 真立体声,`manifest.json` 的 `channels` 变成实际值 |

`engine.js` 本来就用 `StereoPannerNode`,所以这次是**服务端向浏览器看齐**,不是反过来。
一条一轨、什么都不动的工程,现在导出与原曲的**包络相关 0.9999**、
L/R 相关 0.746(原曲 0.747)、电平差 **0.00 dB**。

**明说的限制**:变过调 / 画过音高曲线的块是 PSOLA 重新渲染的,那套算法只吃单声道
⇒ 变调会把那一块的立体声宽度收成居中(不报错、不提示,你知道就好)。

★ 判据在 `tools/selftest_studio.py` 的 `stereo_section()`:左右必须是两个不同的东西、
左 440Hz 右 660Hz 各走各的、居中不减电平、硬推一边另一边真的没了、分轨也是 (n, 2)。

## 发行级导出:真峰 / 抖动 / 标签(2026-10-21)

「能导出 wav」和「能拿去发行」之间隔着三条线,以前一条都没守:

| 问题 | 以前 | 现在 |
|---|---|---|
| 峰值 | 按**采样峰**限在 −0.3 dBFS | 按 **4× 过采样的真峰**限到 **−1.0 dBTP** |
| 位深 | 一律 24 bit | 16 / 24 可选;16 bit 走 **TPDF 抖动**(固定种子,可复现) |
| 采样率 | 固定 48 kHz | 44.1 kHz / 48 kHz,直接按目标率渲染(不二次重采样) |
| 标签 | 没有 | mp3 写 **ID3v2.3**(UTF-16 中文)+ 封面 APIC;wav 插一个 `id3 ` 块(同样内容) |
| 检查 | 没有 | 导出前先量一遍,列出「过 / 不过」 |

**为什么卡真峰**:流媒体会把你的 wav 转成 AAC/Opus,重建波形时采样之间的峰冒出来,
一个「采样峰 −0.3 dBFS」的母带转完就削顶 —— 而你在自己机器上量不出来。
`true_peak_db()` 用 `resample_poly(4,1)` 过采样后取绝对值峰,就是 dBTP。

**为什么 mp3 还要再低 0.6 dB**:lame 编出来的波形和原始采样点不是一回事,
实测同一份母带编成 320k mp3 再解码,真峰从 **−1.00 抬到 −0.73 dBTP**。
所以 mp3 交付按 **−1.6 dBTP** 限(`MP3_CEILING_DB`),实测落地 **−1.33**。

**响度**:BS.1770(K 加权、400ms 块、75% 重叠、−70 绝对门限、−10 相对门限)。
限幅会吃掉一点响度,所以母带是「定增益 → 限真峰 → 量 → 补增益 → 再限」,最多补两次;
补两次还到不了目标就照实写进回执,不硬凑。

### 怎么用

顶栏「导出」打开面板:格式(wav / mp3 320k)、采样率、位深、响度、歌名 / 歌手 / 专辑 /
年份 / 流派 / ISRC、封面(jpg / png,≤8 MB)。
点「检查」走的是**导出同一条混音路**,只量不写文件;点「导出」才落盘。
标签和封面存进工程的 `meta.tags` / `meta.cover`,下次打开还在。

### 交付给谁:自己发行 / 交给唱片公司

面板最上面是二选一,选完下面的字段**跟着变**(不是让你自己拼规格):

| | 自己发行(流媒体) | 交给唱片公司 / 母带师 |
|---|---|---|
| 是什么 | 成品 | **母带前混音**(mixdown) |
| 响度 | −14 LUFS | **不归一** |
| 峰值 | 真峰 −1.0 dBTP | **留 −6 dBFS 余量** |
| 标签 | 写歌名/歌手/封面 | 默认不写 |
| 顺带 | 可勾「再导一版 mp3」 | — |

「留 −6」是**对齐到 −6**,不是「不超过 −6」——低于 −6 的混音会抬上来,
否则同一个人两次导出的电平都不一样,母带师没法对比。
★ 只有在**不归一响度**时这个余量才生效;你要 −14 LUFS 就说明你要成品,峰该由限幅器兜。

实测(同一首 R&B):

```

唱片公司 : -20.02 LUFS · 真峰 -6.00 dBTP · 不带 id3(embed 关)
```

### 明说的限制

- **标签可以关**:交给唱片公司/母带师时默认不写(他们按后台填);自己发行时默认写。wav 是插在 `fmt ` 之后的 `id3 ` 块,mp3 是文件头的 ID3v2.3。
- **ID3 只写 2.3**:2.4 的车机兼容性不如它。帧只有 TIT2/TPE1/TALB/TPE2/TDRC/TRCK/TCON/TSRC/COMM/APIC。
- **真峰是 4× 过采样的估计**,和 TL-DR / Nugen 那种 8× 工具会有 ±0.1 dB 的差,够用。
- **变过调的块是单声道**(PSOLA),这条没变;发行级的宽度只能来自没变调的部分。
- 「检查」用的就是导出那条路,所以它量的是**成品**,不是「大概会怎样」。

★ 判据在 `tools/selftest_studio.py` 的 `release_section()`:fs/4 正弦能看见
采样峰 −3.01 → 真峰 +0.12 的差、限幅后 ≤ −1.000 dBTP、抖动 = 1 LSB 且同种子逐点相同、
削平检测不冤枉满幅正弦、反相被抓、ID3 自己拼自己解、mp3 落盘后标题读得回来。

## 桌面壳:双击出窗口(2026-10-22)

`desktop.py` = 桌面版的入口。它干四件事:**抢空闲端口** → 在本进程线程里把 uvicorn 拉起来
→ 等 `/api/studio/about` 真能应答 → 用 WebView2 开窗口。窗口关掉,`os._exit(0)` 硬退
(音频线程是 daemon,不硬退会在解释器退出阶段卡住)。**单实例**用命名互斥量
`SingMic.Studio.Desktop.v1`,双击第二次弹一句话就退——两个实例改同一个工程会打架。

实测(冻结后的 exe,不是源码):
- 窗口 **1728×928**(屏幕可用区的 9 成,最小 1100×700),标题 `SingMic Studio`;
- 页面 `STUDIO.ready === true`,地址是 `http://127.0.0.1:<随机端口>/studio`(这次是 50201);
- 发 `WM_CLOSE` → 进程退 **0**,不留窗口、不留子进程;
- VST 宿主:`SingMic.exe --vst-worker` 回 `{"ok": true, "pedalboard": "0.9.26"}`;
- 麦克风:`getUserMedia` 在 WebView2 里通,48 kHz / 1 声道,`AudioContext.baseLatency` 0.01 秒。

打包:`python tools/build_app.py` → `dist/SingMic/`(**194 MB**,`--onedir`)。
不用 `--onefile`:每次启动要把几百 MB 解到 temp,冷启动十几秒,DAW 不能这样。

**踩到并已修的四个坑**(每个都表现为「窗口根本不出来」,而且不告诉你为什么):
1. **`-I` 隔离模式不把脚本目录放进 `sys.path`** —— 一跑就是 `No module named 'server'`。
   `server.py` 自己插过一次,`desktop.py` 也得插。
2. **WebView2 的缓存目录必须是我们自己的**。用默认值会跟别的 WebView2 应用抢同一个目录,
   报 `0x800700AA(资源在使用中)`。已固定到 `%LOCALAPPDATA%\SingMic\WebView2`。
3. **冻结后 `sys.executable` 是 SingMic.exe 不是解释器** —— VST 宿主原来用
   `[sys.executable, "-I", worker.py]` 拉子进程,冻结后会**把整个 App 再开一遍**。
   改成「同一个 exe + `--vst-worker` 开关」,`desktop.py` 见到这个开关只进 worker 的 main。
   这个坑必须靠**真跑 exe** 才能发现,源码里跑永远是对的。
4. **USB 隧道自检每 10 秒起一次 adb**(桌面装不了 adb,白起进程)。桌面壳里
   `SINGMIC_NO_ADB=1` 关掉。

PyInstaller 故意排除的:`torch / demucs / transformers / librosa / matplotlib`
(补音是**另一个** Python 环境的事;不排除包会从 194 MB 涨到 2 GB+)。

**还没做的(别当成能做)**:
- 数据目录还在包的 `_internal` 里(便携版能跑,装到 `Program Files` 会被拒写)→ 下一步 `SINGMIC_DATA`;
- 没有安装包(Inno Setup 没装)、没有图标、没有版本信息;
- **麦克风权限弹窗没量过**:上面那次是加了 `--use-fake-ui-for-media-stream` 量的,
  它替人点掉了弹窗。真机上那个弹窗归谁管、点了「允许」之后还记不记得,还没验;
- 窗口窄于 ~1500 px 时顶栏会折成两行(现在默认 1728,不受影响,但小屏笔记本会撞上)。

## 2026-10-22 · 界面语言：五种，设置里可切换

**五种语言**：简体中文（默认跟随系统）、繁體中文、English、日本語、한국어。
入口：设置 → 偏好 → 界面语言。选择存在本机 `~/.singmic/prefs.json`；
「跟随系统」按系统显示语言匹配，匹配不到用简体中文。

**实现**：`web/studio/i18n.js` 的字典以**中文原文为键**，运行时只替换与键完全
相同的文本节点、`title/placeholder/aria-label/alt`，以及由纯排版标签构成的整段
`innerHTML`；切回简体中文时用 `ORIG_*` 快照还原，不做反向翻译。面板重新渲染后
会重新翻译（rAF 去重的 MutationObserver）。

**运行时拼出来的句子不能当键**：`0 块`、`已配置 · 百炼 · key sk-…` 这类由变量
拼出来的文案，字典里既没有、也永远匹配不上，必须在 `t()` 里用 `{0}` 模板现拼。
本轮把效果器名/参数名/分组、块数统计、画布上的提示文字、默认工程名与轨名全部
改成这种写法。

**量具**：`tools/i18n_dom_scan.py --cross` —— 先用中文跑一遍收下所有可见文本，
再用目标语言跑一遍，只报「两种语言下逐字相同」的条目。这是唯一不靠字典自证的
判据（只比对字典键会把没翻的漏掉）。当前结果：英文 0 条；韩文、日文仅剩风格
描述（原样发给 AI 伴奏平台，故意不翻）与在日文里本就同形的词（分析、保存、理解、
生成）；繁體中文只剩简繁同形的字。

**布局**：日语/韩语的按钮比中文长，顶栏与左栏按钮改为 `white-space:nowrap` 允许
整条换行，不再按字折断；效果页侧栏那句说明原来是绝对定位（以整个面板为参照，
于是压到右边滑块上），改为按普通流排在侧栏底部。

**测试**：smoke **251/251**（新增两项 —— 五种语言可选且切换真的换字、设置里有
「界面语言」下拉）。

## 2026-10-22 · 商店打包（MSIX）

**三条命令**：`python packaging\make_icons.py` → `python tools\build_app.py` →
`python packaging\make_msix.py`。产物 `packaging\out\SingMicStudio_<版本>_x64.msix`：
源目录 195 MB，包 84 MB。

**清单**：`Windows.FullTrustApplication` + `runFullTrust` —— 包里就是一个普通桌面程序，
自己起本地服务、自己开 WebView2 窗口，所以不需要任何能力声明。版本号由 `version.py`
补齐成四段（1.0.0 → 1.0.0.0）。包名与发行商必须与 Partner Center 一字不差，
写在 `packaging\identity.json`（不进仓库）；`identity.dev.json` 只用于本机验证流程。

**makeappx 从 NuGet 取**：本机没有 Windows SDK，脚本会自动取
`Microsoft.Windows.SDK.BuildTools` 并解开**整个 x64 目录**。只抠 `makeappx.exe`
一个文件会直接起不来，报 WinError 14001「并行配置不正确」—— 它还要同目录的
appxpackaging.dll / opcservices.dll / ServicingCommon.dll。

**打包后实测**：`dist\SingMic\SingMic.exe` 能起、窗口能出，数据落在
`%LOCALAPPDATA%\SingMic\data`；`/api/studio/about` 的 paths 里 root 是安装目录、
data 是本地数据目录，两者已经分开。

**缺 WebView2 不再白屏**：`desktop.py` 在起服务之前先查注册表与 Edge WebView 目录，
缺了弹一句带下载地址的提示再退出。Windows 11 自带，Windows 10 一般随 Edge 已装。

上架步骤、后台要填的字段、隐私政策成稿与商店文案在 `packaging/README.md` 和
`packaging\store\`。
